# AutoGamble 1.3.1 — live Baltop targeting fix

Live testing confirmed that the in-game crawler populated 389 pages and 15,975 players, but 1.3.0 sent no payments at 100% Baltop. The local cache contained 15,971 players above the 500M minimum; the pool and weights were not empty. The verifier used a completed `/pay username` argument, unlike the 1.2.4 prefix suggestion flow. It now shares the 1.2.4 Brigadier request path, tests one-, two-, then three-character-truncated prefixes for an exact username match, and advances to another candidate after failure. Up to 30 different players are checked per cycle by default (configurable 1–100), with 250ms between suggestion requests. Zero-weight methods remain disabled.

The cache also exposed missing ranks and one false rank parsed from a username beginning with `Rank1`. Newly scanned pages derive missing ranks from the observed 54-slot GUI geometry and item slot (five player rows), while explicit ranks take precedence. Legacy mixed-rank caches display in descending balance order, which preserves the actual leaderboard order without inventing exact historical slot positions. Rank, balance ascending/descending, username and source-page sorts remain available.

The Scanned Baltop page now has a Targeting Debug tab showing balance eligibility, exclusions, candidate checks, suggestion requests, online matches, payment attempts/results, and the last rejection. Existing cache and settings migrate without reset. The old 1.3.0 release artifacts are archived before this version is published. A repeat live DonutSMP test is still needed to confirm exact suggestion responses and real payment dispatch.
